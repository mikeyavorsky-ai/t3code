# Privacy fork implementation plan

Base reviewed: `voice-tweak` at `0f55a0dc`. The [telemetry audit](../t3code-telemetry-audit.md) covers upstream at `d6061ec8ad`. Implementation and release-build network verification are pending.

## Intended behavior

Local use, direct iOS pairing over Tailscale, and macOS SSH forwarding continue to work. Starting T3, viewing a conversation, or reconnecting to an environment should contact only the selected server or SSH peer. Explicit actions such as sending a turn to a configured provider can contact the chosen destination. This scope covers traffic initiated by T3 itself on the client and server, including a server launched over SSH.

Maintain the fork as small, independently verifiable patches at service boundaries. Preserve shared contracts, migrations, and stored direct-pairing credentials wherever possible. When an upstream SDK or fallback can still initiate a request, remove or disable it even if that adds rebase work.

## Patch sequence

1. **Disable server analytics, feedback, and diagnostic exports.** Bind an inert [AnalyticsService](apps/server/src/telemetry/AnalyticsService.ts) before telemetry identity creation or queue initialization. Have record return false and make owner recording and flushing no-ops. Disable [feedback intake](apps/server/src/feedback/FeedbackService.ts), including automatic reports, queued delivery, and approval UI. Disable relay tracing and server and desktop network OTLP exporters even when environment, managed policy, or saved settings supply endpoints. Keep local logs.
2. **Remove mobile reporting at startup.** Remove Expo Observe initialization, the direct SDK use in the [render error boundary](apps/mobile/src/components/RenderErrorBoundary.tsx), and any native build integration that installs a reporter. Preserve local error handling. Disable connection trace export and omit endpoints and credentials from the [release config](apps/mobile/app.config.ts). Remove the two obsolete diagnostics switches. Verify with diagnostics previously enabled.
3. **Disable T3 Connect across clients and host.** Return unavailable from the server, web, desktop, and mobile capability paths. Prevent Clerk initialization, cloud onboarding, managed tunnel startup, relay workers, agent activity publication, and relay push registration. Reject explicit Connect actions locally, including CLI entry points. Ignore saved cloud links during startup and reconnect. Preserve direct pairing and session authentication. Keep dormant code, migrations, and wire types where they do not cause network activity. This removes account discovery, relay access, relay notifications, and relay-backed Live Activities.
4. **Control updates and remote server provisioning.** Disable Electron update checks and Expo OTA updates at both native launch and JavaScript entry points. Distribute fork builds manually. Check server and provider maintenance paths for automatic registry lookups. Preserve macOS SSH forwarding and pairing. The initial implementation should require a matching fork server already installed on the remote host and report how to install it when missing. Eliminate the automatic upstream download. An ordinary SSH forward to a running fork server should continue to work. On iOS, pair directly to the server’s tailnet HTTPS address. Generate direct pairing links and serve the browser client from the server itself. See [remote access](docs/user/remote-access.md).
5. **Remove third-party requests during ordinary use.** Remove the GitHub star prompt trigger from the [composer](apps/web/src/components/chat/useComposerSend.ts), including its message counting, idle monitoring, and authenticated lookup. Preserve user-initiated GitHub operations. Replace [Google favicon requests](packages/shared/src/favicon.ts) with bundled icons. Check web and mobile renderers for external Markdown images and provider-supplied icons, including persisted content. Use local placeholders for remote assets and keep links clickable. Verify that local attachments still render.
6. **Keep voice requests explicit.** Run local transcription against installed models. Require an explicit action to download a missing model through the [model store](apps/server/src/speech/SpeechModelStore.ts). Require an explicit cloud provider choice before transmitting audio. Check [cloud speech](apps/server/src/speech/CloudSpeech.ts) for model catalog requests triggered by startup or settings rendering.

## Release verification and future rebases

- Build the fork’s macOS, server, and iOS release artifacts. Test the server-hosted web client too. Development and CI defaults can suppress requests that a release makes.
- Run the same flows with fresh isolated state and with a copied prior installation containing a saved Connect login, direct pairing, diagnostics enabled, and configured exporter endpoints. Include a queued feedback report and previously enabled activity sharing.
- Capture DNS and outbound connection attempts on the client and remote host. Use a local replay provider and a thread containing an external link, image, and provider icon. Exercise cold launch, idle, thread rendering, six message sends followed by focused idle, background and foreground, and reconnect. Check update controls, voice settings, and SSH startup with a missing remote binary.
- Confirm a complete turn over local, Tailscale, and SSH connections, and verify that direct credentials survive restart. Fail the privacy check on any unexpected T3-initiated destination, including failed attempts. Verify explicit provider and model-download actions separately.
- Repeat the network checks after upstream rebases. Review new startup workers, native plugins, update feeds, and renderers when a check fails. Keep each patch scoped to its service or entry point so unaffected upstream changes merge cleanly.
